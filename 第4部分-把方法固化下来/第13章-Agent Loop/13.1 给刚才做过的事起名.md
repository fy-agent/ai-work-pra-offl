# 13.1 给刚才做过的事起名

## 这节解决什么问题

第 1–3 部分已经做过：交任务、给材料、看过程、核对、交周报和纪要。这一部分只是给这些动作起名字，方便以后复盘。没有新魔法。

## 先记住什么

一次成功（或诚实失败）的任务里，通常能看见四截：

1. **计划**：它准备干什么
2. **工具**：它实际去读文件、写文件、搜索
3. **产物**：有没有留下能打开的文件
4. **反馈**：你是否打断、它是否停下来问

这四截合起来，叫一次 Agent Loop。名字不重要。你要能指着屏幕说：刚才计划在哪、工具在哪、产物在哪、你有没有接手。

2026-08-20 在 WorkBuddy 上实跑过一件虚构月报。发出去之后：左栏出现这条任务，中间先是「准备中」，再是「深度思考」和「读取中」，输入区的发送键变成停止。这就是过程，不是聊天框里又多了一段作文。

## 当场怎么做

1. 打开你最近一次任务（成功或失败都行）。
2. 按四截把过程抄进一张复盘卡，各写一行事实，不要写「它很聪明」。
3. 找一处中途纠正或停问。没有纠正，就写「我从头到尾没接手」。

## 怎么检查

过：四截都有对应的屏幕证据；术语能对上自己的任务，不是抄定义。

返工：卡上全是概念，指不出左栏、中间、结果文件。

## 常见翻车

任务失败就觉得「没 Loop」。读文件失败、停下来问你，也是 Loop。缺的是产物，不是过程。

## 最小例子

这次月报实跑：计划是写 `月报_v1.md`；工具去读了表和上月样例；产物没有生成，因为它在工作副本里找不到那两份文件；反馈是它列出「不存在」，请你确认路径，没有编数字交差。四栏能填。

## 来源与时效

界面词「准备中 / 深度思考 / 读取中」会改。四截不会。当天入口见 [附录 A](../../附录/A-入口与额度更新卡.md)。
