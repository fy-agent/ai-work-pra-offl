# 17.1 大任务先拆，批准点由人放行

## 这节解决什么问题

月报、纪要、三版报告一起丢进去，让它「从头跑到尾」。中间没有你点头的地方，错会铺到每一份产物。

## 先记住什么

先拆子任务，标依赖，标每一段的输出和验收。小样本 → 你批准 → 再扩展。

无批准点的全自动是失败版。批准点由人放行，不是由模型宣布「已完成」。

多角色、多 Agent 只有在子任务独立、交接清楚、并行真有收益时才拆。入门可以不拆人，只拆步骤。

## 当场怎么做

把「三版经营报告」拆成：锁口径 → 执行版 → 判断版 → 口头版。每一段验收过了，再开下一段。口径表是第一段的产物。

## 怎么检查

过：拆解表上每段有输出和验收；至少有一个批准点在批量写之前。

返工：一张卡写「全部生成」。

## 常见翻车

把多 Agent 当炫技。一个人按顺序批准，往往更稳。

## 最小例子

这次月报本应是：选空间 → 确认两份材料在 → 预览结构 → 写 v1。实跑在第一段就停了，因为材料不在。停在批准点，而不是带着空材料写三版。

## 来源与时效

产品若有 Plan 模式，当作「先报计划」的入口，不要当无人批准。

## 状态

候选读本。不是已批准课程。
