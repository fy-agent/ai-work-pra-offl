# 20.1 现场崩了谁喊停

## 这节解决什么问题

活动流程写得很满，没有负责人，设备挂了也没 Plan B。选修活动课要的是带停问点的流程，不是漂亮日程表。

## 先记住什么

先关键路径：谁、何时、依赖什么、失败喊谁停。三阶段（准备 / 现场 / 收尾）每段至少一个停问点。

设备失败无 Plan B，是失败版。只补受影响的行，不重排整天。

通知仍是草稿。工作台不发短信、不发群。附录 C 的禁区在这里同样有效。

## 当场怎么做

1. 用一场虚构工作坊或你有权筹划的小活动。
2. 任务：交流程 v2 + 三阶段日程 + 一列 Plan B；每行有负责人；设备、场地、材料各有一条失败时怎么降级。
3. 推演一次「投影挂了」。只改依赖投影的行。
4. 小活动复跑同一模板。通知栏保持草稿。

## 怎么检查

过：每段有停问；负责人不是「相关同学」；Plan B 能执行；通知未发出。

返工：日程很密，没人名字；或已生成群发文案并暗示可一键发送。

## 常见翻车

把报名 36 人写进「已确认到场」。报名不是出勤。

## 最小例子

现场段：投影失败 → 停问人=主持；Plan B=口播 + 印好的一页周报样例；不改开始时间，除非主持批准。失败流程：设备失败后仍写「原计划进行」。

## 来源与时效

日历软件会变。停问点和 Plan B 不变。

## 状态

候选读本。不是已批准课程。
