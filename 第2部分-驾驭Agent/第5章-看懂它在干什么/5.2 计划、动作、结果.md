# 5.2 计划、动作、结果

## 这节解决什么问题

知道要看过程，却把窗口里滚动的字全抄下来。那不是记录，是流水账。先把看得见的过程切成三截，再加上你允许它继续的检查点。

## 先记住什么

执行记录最少四格：

| 格 | 写什么 |
| --- | --- |
| 计划 | 准备读哪些材料、按什么规则、写入哪个新文件 |
| 动作 | 实际读了什么、筛了什么、写了什么 |
| 结果 | 预览、异常、新文件名 |
| 检查点 | 批量写入前 / 覆盖原件前 / 导出或发送前 |

每一格还能对应第 2 章的「看、决定、做、再看」。这里不再起新名字，只是把过程写成你能打断的句子。

计划是它开工前说的。动作是它实际做的。对不上，就停，不要等最终文件。

## 当场怎么做

复制下面空表，跑一次小任务时边看边填：

```text
计划：
动作：
结果：
检查点：
决定：继续 / 改方向 / 停止
干预（如有）：
```

填的时候用你看见的事实，不要用「它思考了很久」。读了哪个文件、写了哪个文件、有没有预览，必须能指出来。

聊天记录和结果文件要能对上同一件事：记录说写了 `月报_v1.docx`，结果区就要有这份文件。

## 怎么检查

过：四格都有字；计划和动作能分开；检查点出现在写、覆盖或发送之前，而不是事后感想。

返工：只有「结果：已完成」；或决定栏空白，等于你从头到尾没接过手。

## 常见翻车

把模型内部的 Thought / 推理摘要抄进记录。你要的是可观察的动作：读文件、改文件、问你、停。

计划写得很完整，动作栏复制计划。动作必须是事后看到的，允许和计划不一致——不一致正是你要找的地方。

## 最小例子

李明的一格记录：

- 计划：读 `月度数据.xlsx` 的「活动场次」列，预览 5 行，写入新文件 `月报_v1.docx`，不覆盖上月样例
- 动作：实际读了「备注」列
- 结果：预览第一行是「可能十几场」
- 检查点：尚未写入月报
- 决定：停止，改成指定列名后再预览

这一次没有生成错误月报。记录的价值就在这里。

## 来源与时效

表格是给人填的。不必做成某种日志格式。换工作台时，你自己的 `执行记录.md` 可以原样再用。
