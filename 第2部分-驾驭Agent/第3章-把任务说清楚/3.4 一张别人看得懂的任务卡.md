# 3.4 一张别人看得懂的任务卡

## 这节解决什么问题

格子填满了，自己读着明白，别人看仍不知道要交什么。任务卡的验收不是「我写得很全」，而是：一个没听你讲话的人，只看这张卡，能说出产物长什么样。

## 先记住什么

把卡交给工作台之前，先给人看。

同伴只看卡，不看会议原话，预测：

- 会得到什么文件
- 大概多长
- 哪一类内容必须有
- 哪一类内容不该出现

预测对不上你心里要的，就只改没说清的那几句，不要整张推翻，也不要加新任务。

第二版和第一版的差别，要能指回「刚才哪一句没说」。指不回去，说明你在凭感觉重做。

## 当场怎么做

1. 用下面这张虚构好卡当样子，改你自己上周失败的那一句。不要另换一个更大的题目。
2. 把 Before（原话）和 After（改写卡）抄在一起，方便以后对照。
3. 请另一个人只看 After，口头预测产物。你不许补充「其实我是想……」。
4. 用 After 跑一次，打开 v1，对照验收项。
5. 只改仍被猜的那一段，存 v2。

模板（每段只答一个问题）：

```text
【任务】我要你做什么？

【背景】为什么做？给谁用？看完做什么？

【材料】依据什么信息？哪些不放？

【要求】必须做到什么？（能打勾的）

【边界】哪些不能做？不知道怎么办？

【交付】最后给我什么文件、多长、什么结构、叫什么名字？

【验收】结果出来，哪几项能打勾？
```

## 怎么检查

过：别人只看卡能说出文件名和结构；v1 的问题能指回某一格；v2 只动了那一格。

返工：你必须在旁边口头解释卡；或 v2 把全文重写了一遍。

## 常见翻车

把卡写给「懂你们组黑话的人」。黑话对工作台和对新来的同事一样不透明。岗位名、缩写、内部项目代号，要么解释一句，要么当作未知标待确认。

验收写「领导满意」。领导不在检查现场。把满意拆成能打开、结构对、数字回得去、没有把待确认写成事实。

## 最小例子

Before：

> 帮我根据这份会议记录做一个汇报。

After（虚构，可直接改着练）：

```text
【任务】根据会议记录，整理会前材料，给主管 10 分钟看完。

【背景】明天下午项目复盘。主管要判断：决定了什么、什么还没定、下周谁做什么。

【材料】只用「会议记录.md」。不要网搜，不要补充记录里没有的预算数字。

【要求】一页；分成决定、待确认、行动项；每条行动尽量有人和日期。

【边界】记录没写的负责人写成待确认，不要指定。预算未批不要写成已落实。不要发给任何人。

【交付】Word 文件，名称为 复盘会前材料_v1.docx。不要做幻灯片。

【验收】能打开；三块都有内容；至少一条待确认仍是待确认；行动项不是空的；原记录里没有的数字没被编出来。
```

同事只看这张卡，应能说出：一份一页的 Word，不是长篇综述，预算那件事不能写成已经定了。

## 来源与时效

任务卡是给人看的工作说明，不是提示词秘籍。换工作台时，卡可以原样再跑一次，用来比较的是产物和验收，不是界面。
