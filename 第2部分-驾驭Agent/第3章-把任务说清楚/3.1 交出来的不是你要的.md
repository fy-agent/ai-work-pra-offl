# 3.1 交出来的不是你要的

## 这节解决什么问题

工作台会交文件了，可交出来的汇报不是你脑子里要的：太长、没受众、把猜测写成了决定。第一反应往往是「模型不行」。很多时候，问题出在那句任务上。

## 先记住什么

脑子里的要求和说出口的话，经常不是一回事。

一句常见的原话：

> 帮我根据这份会议记录做一个汇报。

这里没说给谁看、多长、交什么文件、哪些话不能猜。工作台只能猜。猜得流畅，不等于猜对。

今天先看见不对，先不要背框架，也不要先换模型。

## 当场怎么做

1. 用上面那句原话，加上一份虚构会议记录，交给工作台跑一次。把产物存成 `汇报_v0.docx`。
2. 打开文件，对照你脑子里要的规格：给谁、几页、要不要行动项、不确定的事能不能写成事实。
3. 先投票给自己：问题主要在模型，还是在任务没说清。写下一句理由。
4. 圈出原话里没说的部分。圈不出来，说明你还觉得「做个汇报」已经够清楚——下一节用三问拆。

先别改提示词堆形容词。下一节不靠「更专业」来补缺口。

## 怎么检查

过：你能指出 v0 和心里规格差在哪，并且至少圈出原话里缺的两项（例如受众、长度、文件名、不能猜的事）。

返工：结论只有「它不够聪明」；或 v0 你根本没打开，只看了聊天摘要。

## 常见翻车

同一份会议记录，两个人用同一句「做个汇报」，得到完全不同的文件，却去比较哪次模型更好。先把任务写到一个没听你讲话的人能预测产物，再谈模型。

把失败文件删掉，只留「最新版」。后面你就没法指回：第一次错在哪句没说。

## 最小例子

虚构会议记录里有三句话：活动改到周五；预算还没批；李明负责通知场地。

原话跑出来的 `汇报_v0.docx` 是一篇 800 字「会议精神综述」，预算写成「已落实」，也没有行动表。李明要的是：给主管看的一页纸，三条决定、两条待确认、一张行动表，文件名 `复盘会前材料_v1.docx`。

差的不是文笔。是任务里没说「一页」「给主管」「待确认不能写成已落实」。

## 来源与时效

「先怀疑任务，再怀疑模型」是稳定工作法。不依赖某个软件的模式名。
